## 4. 프로젝트 데이터 구조

- `ProjectStatus`: `planning`, `developing`, `released`
- `ProjectLink`: 링크 유형, 라벨, href 구조
- `ProjectMember`: 이름과 역할
- `Project`: slug, summary, description, optional thumbnail, status, tags, featured, members, links, dates 포함
- mock data: 3개
- featured 프로젝트: 2개
- 상태 구성: `planning` 1개, `developing` 1개, `released` 1개

실제 외부 URL이 제공되지 않았기 때문에 모든 샘플 프로젝트의 `links`는 빈 배열입니다.

## 5. 구현 결과

- 프로젝트 카드: 제목, summary, 상태 배지, 태그, 상세 링크, CSS placeholder 이미지 표시
- 프로젝트 목록: `getAllProjects()` 기반 1/2/3열 반응형 그리드
- 프로젝트 상세: 제목, 상태, 태그, 소개, 기간, 구성원, 관련 링크, 목록 복귀 링크 표시
- 상태 배지: raw enum 대신 `기획 중`, `개발 중`, `공개됨` 표시
- 태그: 작은 배지로 표시, 링크처럼 보이지 않게 처리
- 참여 구성원: 팀 단위 샘플 역할 표시
- 외부 링크: 실제 href가 있을 때만 새 탭 보안 속성으로 렌더링
- 404 처리: 없는 slug는 `notFound()`와 프로젝트 전용 404 페이지 사용
- 동적 metadata: 프로젝트별 title/summary 사용
- 메인 대표 프로젝트: `getFeaturedProjects(3)`로 같은 mock data 재사용

## 7. 접근성

- 목록 페이지는 하나의 `<h1>` 유지
- 상세 페이지는 프로젝트 제목을 `<h1>`로 사용
- 상세 섹션 제목은 `<h2>` 사용
- 상세 링크는 `{프로젝트명} 상세 보기`처럼 목적이 드러나게 작성
- CSS placeholder 이미지는 `aria-hidden` 처리
- 상태는 색상뿐 아니라 한국어 텍스트로 표시
- 프로젝트, 태그, 멤버, 링크는 목록 구조 사용
- 외부 링크가 생길 경우 `target="_blank"`와 `rel="noreferrer noopener"` 적용
