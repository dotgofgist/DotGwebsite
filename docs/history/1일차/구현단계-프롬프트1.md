현재 작업 중인 저장소는 게임창작부 동아리 웹사이트 `DotG`다.

이번 작업은 새로운 개발 페이즈의 **프롬프트 1: Supabase DB 스키마와 로컬 마이그레이션 구축**에 해당한다.

# 8. Migration 구성

기존 migration이 없다면 Supabase CLI를 사용해 다음 두 migration을 생성한다.

```powershell
pnpm supabase migration new create_initial_content_schema
pnpm supabase migration new add_initial_rls_policies
```

생성되는 실제 timestamp 파일명을 사용한다.

예상 구조:

```text
supabase/migrations/
├─ <timestamp>_create_initial_content_schema.sql
└─ <timestamp>_add_initial_rls_policies.sql
```

## 첫 번째 migration 책임

```text
create_initial_content_schema
```

다음 내용을 포함한다.

* enum
* table
* constraint
* index
* helper function
* timestamp trigger
* profile 생성 trigger

## 두 번째 migration 책임

```text
add_initial_rls_policies
```

다음 내용을 포함한다.

* grant
* RLS 활성화
* 공개 조회 정책
* 관리자 및 편집자 관리 정책
* profile 접근 정책

기존 migration이 존재한다면 새 migration만 추가한다.

기존 migration 파일을 수정하지 마라.

# 10. profiles 테이블

다음 테이블을 생성한다.

```text
public.profiles
```

필드:

```text
id
display_name
role
created_at
updated_at
```

권장 SQL 의미:

```sql
id uuid primary key references auth.users(id) on delete cascade
display_name text
role public.user_role not null default 'member'
created_at timestamptz not null default now()
updated_at timestamptz not null default now()
```

규칙:

* `id`는 `auth.users.id`와 동일한 UUID를 사용한다.
* 비밀번호나 access token을 저장하지 않는다.
* 이메일을 중복 저장하지 않는다.
* role 기본값은 `member`다.
* role 변경은 이후 관리자 정책으로 제한한다.

# 11. 신규 사용자 profile 자동 생성

`auth.users`에 사용자가 생성되면 `public.profiles`에도 기본 profile이 생성되도록 준비한다.

함수 예시 이름:

```text
public.handle_new_user()
```

트리거 예시 이름:

```text
on_auth_user_created
```

규칙:

* `security definer`를 사용한다.
* 명시적인 `search_path`를 설정한다.
* `id`는 `new.id`를 사용한다.
* `display_name`은 사용자 metadata에 값이 있는 경우에만 사용한다.
* role은 항상 `member`로 생성한다.
* 동일 ID 충돌에 안전해야 한다.
* 실제 사용자나 관리자 계정을 migration에 생성하지 않는다.

title text not null

status public.project_status not null default 'planning'

* 빈 제목 금지
* 빈 summary 금지
* 빈 description 금지

`thumbnail_path`에는 완전한 공개 URL보다 향후 Storage 내부 경로를 저장할 수 있도록 설계한다.

이번 단계에서는 Storage를 만들지 않는다.

* 테스트가 통과하는가

migration 오류를 우회하기 위해 DB를 수동으로 수정하지 마라.

* DB trigger로 과도한 비즈니스 로직을 구현하지 않는다.
