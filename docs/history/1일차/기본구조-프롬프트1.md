현재 작업 중인 저장소는 게임창작부 동아리 웹사이트 프로젝트다.

## 기술 스택

* Next.js 16 App Router
* React 19
* TypeScript
* Tailwind CSS 4
* pnpm
* 향후 Supabase 연동
* 향후 Vercel 배포

프로젝트는 이미 `create-next-app`으로 생성되어 있다.

절대로 다음 작업을 하지 마라.

* `create-next-app` 재실행
* 프로젝트 전체 재생성
* 기존 Git 저장소 초기화
* 기존 설정 파일 전면 교체
* 불필요한 패키지 설치
* Supabase 실제 연결
* 관리자 인증 구현
* 실제 CRUD 구현
* 페이지의 완성형 디자인 구현

이번 작업은 7단계 중 **프롬프트 1: 프로젝트 구조와 공통 기반 구축**에 해당한다.

# 3. 목표 라우팅 구조

Next.js App Router와 Route Group을 사용한다.

공개 사이트는 `src/app/(public)` 아래에 배치한다.

`(public)`은 Route Group이므로 실제 URL에 포함되지 않아야 한다.

관리자 로그인과 관리자 대시보드는 서로 다른 레이아웃을 사용할 수 있도록 분리한다.

다음 라우팅 구조를 생성하라.

```text
src/app/
├─ layout.tsx
├─ globals.css
├─ not-found.tsx
│
├─ (public)/
│  ├─ layout.tsx
│  ├─ page.tsx
│  │
│  ├─ about/
│  │  └─ page.tsx
│  │
│  ├─ projects/
│  │  ├─ page.tsx
│  │  └─ [slug]/
│  │     └─ page.tsx
│  │
│  ├─ recruitment/
│  │  └─ page.tsx
│  │
│  ├─ notices/
│  │  ├─ page.tsx
│  │  └─ [slug]/
│  │     └─ page.tsx
│  │
│  └─ contact/
│     └─ page.tsx
│
└─ admin/
   ├─ login/
   │  └─ page.tsx
   │
   └─ (dashboard)/
      ├─ layout.tsx
      ├─ page.tsx
      │
      ├─ projects/
      │  ├─ page.tsx
      │  ├─ new/
      │  │  └─ page.tsx
      │  └─ [id]/
      │     └─ edit/
      │        └─ page.tsx
      │
      ├─ notices/
      │  ├─ page.tsx
      │  ├─ new/
      │  │  └─ page.tsx
      │  └─ [id]/
      │     └─ edit/
      │        └─ page.tsx
      │
      ├─ recruitment/
      │  └─ page.tsx
      │
```

```text

/admin/notices
/admin/notices/new
/admin/notices/[id]/edit
/admin/recruitment

```

## 라우팅 주의사항

* 기존 `src/app/page.tsx`와 `src/app/(public)/page.tsx`가 동시에 `/` 경로를 만들지 않도록 정리하라.
* 기존 기본 홈페이지 코드는 필요한 경우 `(public)/page.tsx`로 이동하거나 대체하라.
* Route Group 이름은 실제 URL에 나타나지 않아야 한다.
* 동적 경로의 매개변수는 Next.js 16의 현재 타입 규칙에 맞게 처리하라.
* 존재하지 않는 동적 데이터 처리 로직은 아직 구현하지 않는다.
* 동적 페이지는 전달된 `slug` 또는 `id`를 임시로 화면에 출력해도 된다.

# 4. 임시 페이지 작성 규칙

모든 경로는 `pnpm build`가 성공하도록 최소한의 실행 가능한 `page.tsx`를 가져야 한다.

임시 페이지에는 다음 정도만 표시한다.

* 페이지 제목
* 해당 경로의 용도
* 이후 단계에서 구현할 기능을 나타내는 짧은 설명

예시:

```tsx
import { Container } from "@/components/ui/container";
import { SectionHeading } from "@/components/ui/section-heading";

export default function AboutPage() {
  return (
    <Container className="py-16">
      <SectionHeading
        title="동아리 소개"
        description="동아리 소개 콘텐츠는 후속 단계에서 구현합니다."
      />
    </Container>
  );
}
```

페이지마다 과도한 마크업이나 완성형 디자인을 작성하지 마라.

같은 임시 UI를 반복해야 한다면 재사용 가능한 컴포넌트로 분리할 수 있지만, 불필요한 추상화는 피하라.

모든 페이지 UI는 한국어로 작성한다.

```ts
export const metadata: Metadata = {
```

현재 프로젝트에 이미 적절한 폰트 설정이 있다면 최대한 유지하라.

# 8. 공통 컴포넌트 구조

다음 폴더를 만든다.

```text
src/components/
├─ layout/
├─ ui/
└─ shared/
```

빈 폴더만 생성하지 마라.

이번 단계에서는 `components/ui`에 다음 파일을 구현한다.

```text
src/components/ui/button.tsx
src/components/ui/card.tsx
src/components/ui/container.tsx
src/components/ui/section-heading.tsx
src/components/ui/badge.tsx
src/components/ui/input.tsx
src/components/ui/textarea.tsx
```

## 공통 UI 구현 규칙

* TypeScript를 사용한다.
* `any`를 사용하지 않는다.
* Tailwind CSS만 사용한다.
* 외부 UI 라이브러리를 추가하지 않는다.
* `forwardRef`는 실제로 필요한 입력 컴포넌트에만 사용한다.
* 브라우저 상태가 필요하지 않으므로 `"use client"`를 추가하지 않는다.
* 기본 HTML 속성을 전달할 수 있도록 타입을 설계한다.
* 사용자가 추가한 `className`을 기본 클래스와 병합할 수 있게 한다.
* 접근 가능한 기본 HTML 요소를 사용한다.
* Button은 최소한 `button`, `Link` 등에서 스타일을 재사용할 수 있도록 클래스 생성 방식이나 `className` 확장을 고려한다.
* 지나치게 복잡한 variant 시스템은 만들지 않는다.
* `class-variance-authority`, `clsx`, `tailwind-merge` 같은 패키지를 새로 설치하지 않는다.

## 각 컴포넌트 역할

### `container.tsx`

* 콘텐츠 최대 너비 적용
* 좌우 반응형 여백 적용
* `className` 전달 지원
* 기본 요소는 `div`

### `section-heading.tsx`

최소 props:

```ts
type SectionHeadingProps = {
  title: string;
  description?: string;
  className?: string;
};
```

### `button.tsx`

최소 지원 형태:

```text
primary
secondary
ghost
danger
```

최소 지원 크기:

```text
sm
md
lg
```

### `card.tsx`

다음 단위로 사용할 수 있게 한다.

```text
Card
CardHeader
CardTitle
CardDescription
CardContent
CardFooter
```

### `badge.tsx`

프로젝트 상태와 공지 고정 여부 등에 재사용할 수 있는 단순한 배지를 구현한다.

### `input.tsx`

기본 `<input>` 속성을 지원하고, focus 상태와 disabled 상태를 시각적으로 구분한다.

### `textarea.tsx`

기본 `<textarea>` 속성을 지원하고, 최소 높이를 설정한다.

# 9. 유틸리티

다음 구조를 생성한다.

```text
src/lib/
└─ utils/
   └─ cn.ts
```

`cn.ts`는 외부 패키지를 설치하지 않고 문자열 기반 `className`을 안전하게 결합하는 간단한 함수로 작성한다.

예시 기능:

```ts
export function cn(
  ...classes: Array<string | false | null | undefined>
): string {
  return classes.filter(Boolean).join(" ");
}
```

필요 이상으로 복잡한 Tailwind 클래스 충돌 해결 로직을 직접 구현하지 마라.

날짜, slug, 파일 유틸리티는 아직 만들지 않는다.

# 12. 전역 스타일

기존 `src/app/globals.css`를 먼저 읽고 Tailwind CSS 4 설정 방식을 유지한다.

전역 스타일은 다음 원칙으로 최소한만 정리한다.

* 기본 배경색
* 기본 텍스트 색상
* `box-sizing`
* 이미지 최대 너비
* 링크 및 버튼의 기본 상속
* focus-visible 접근성
* 부드러운 스크롤은 사용자의 모션 감소 설정을 침해하지 않게 처리
* 360px 모바일 화면에서 기본 가로 스크롤이 발생하지 않도록 구성

사이트는 향후 어두운 게임 개발 동아리 디자인을 적용할 예정이므로 다음 CSS 변수를 준비한다.

```css
:root {
  --background: #ffffff;
  --foreground: #171717;
  --surface: #f5f5f5;
  --border: #e5e5e5;
  --primary: #6d5dfc;
  --primary-foreground: #ffffff;
}

@media (prefers-color-scheme: dark) {
  :root {
    --background: #0a0a0a;
    --foreground: #ededed;
    --surface: #171717;
    --border: #2a2a2a;
  }
}
```

현재 기본 프로젝트의 변수 구조가 이미 적절하다면 이를 확장하는 방식으로 작성하라.

이번 단계에서 화려한 애니메이션이나 완성형 디자인은 구현하지 않는다.

* `.env.local`은 생성하거나 수정하지 마라.
* 실제 키를 작성하지 마라.
* `.env.example`에는 비밀 정보를 넣지 마라.
* `.gitignore`에서 `.env.local`과 실제 환경 변수 파일이 무시되는지 확인하라.
* `.env.example`은 Git에 포함될 수 있어야 한다.
* 아직 Supabase 클라이언트 파일을 만들지 마라.

# 15. 구현 규칙

다음 규칙을 반드시 준수하라.

* TypeScript를 사용한다.
* `any` 사용을 피한다.
* Server Component를 기본값으로 사용한다.
* 이번 단계에서는 Client Component를 만들지 않는다.
* 페이지 파일은 최소한의 조합 코드만 포함한다.
* 공통 UI는 `src/components/ui`에 둔다.
* 기능별 코드는 향후 `src/features`에 둔다.
* 사이트 설정은 `src/config`에 둔다.
* 외부 패키지를 새로 설치하지 않는다.
* 기존 의존성 버전을 변경하지 않는다.
* CSS Module을 사용하지 않는다.
* styled-components를 사용하지 않는다.
* Shadcn UI를 설치하지 않는다.
* 아이콘 패키지를 설치하지 않는다.
* 불필요한 배럴 파일을 만들지 않는다.
* 실제 Supabase 코드를 작성하지 않는다.
* 실제 관리자 인증을 작성하지 않는다.
* 실제 데이터 조회 또는 CRUD를 작성하지 않는다.
* 모든 텍스트는 기본적으로 한국어를 사용한다.
* 시맨틱 HTML을 사용한다.
* 키보드 focus 표시를 제거하지 않는다.
* 기존 파일을 확인하지 않고 덮어쓰지 않는다.
* 프로젝트 루트 밖의 파일을 수정하지 않는다.

# 16. 검증

구현 완료 후 다음 명령을 순서대로 실행하라.

```powershell
pnpm lint
pnpm build
```

오류가 발생하면 원인을 분석하고 코드 문제를 수정한 다음 다시 실행하라.

다음 사항도 확인하라.

* `/` 경로 충돌이 없는가
* 공개 Route Group이 URL에 노출되지 않는가
* 관리자 로그인에 대시보드 레이아웃이 적용되지 않는가
* 모든 정적 페이지가 빌드되는가
* 동적 프로젝트 경로가 빌드되는가
* 동적 공지사항 경로가 빌드되는가
* TypeScript 오류가 없는가
* ESLint 오류가 없는가
* 사용하지 않는 import가 없는가
* 환경 변수가 없어도 빌드되는가
* 360px 화면에서 기본 레이아웃이 가로로 넘치지 않는가

개발 서버가 실행 중이라 `.next` 관련 잠금 문제가 발생한다면 코드 오류와 구분하여 설명하라. 임의로 사용자 프로세스를 강제 종료하지 마라.
