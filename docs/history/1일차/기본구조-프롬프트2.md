현재 작업 중인 저장소는 게임창작부 동아리 웹사이트 프로젝트다.

이번 작업은 7단계 중 **프롬프트 2: 공개 사이트 레이아웃과 모바일 내비게이션 구현**에 해당한다.

프롬프트 1에서 다음 기반 작업이 완료되었다고 가정한다.

* Next.js App Router 라우팅 골격
* `src/app/(public)` Route Group
* 공개 페이지의 임시 화면
* `src/components/ui` 공통 UI
* `src/config/site.ts`
* `src/config/navigation.ts`
* `src/lib/utils/cn.ts`
* 기본 전역 스타일
* 관리자 경로 골격

기존 구현을 먼저 확인하고, 실제 파일 상태에 맞춰 필요한 부분만 수정하라.

프로젝트를 다시 생성하거나 기존 구조를 전면 교체하지 마라.

# 1. 작업 목표

공개 사이트 전체에서 공통으로 사용하는 다음 요소를 구현한다.

1. 공개 사이트 Header
2. 데스크톱 내비게이션
3. 모바일 햄버거 메뉴
4. 공개 사이트 Footer
5. 현재 경로에 따른 활성 메뉴 표시

8. 공개 사이트 Route Group 레이아웃에 Header와 Footer 연결

* 공지사항 목록
* 모집 안내 콘텐츠
* 관리자 Header와 Sidebar
* Supabase 연결
* 로그인 및 인증
* 실제 데이터 조회
* 외부 UI 라이브러리 설치
* 복잡한 애니메이션

# 4. 공개 Header 요구사항

다음 파일을 구현한다.

```text
src/components/layout/public-header.tsx
```

Header에는 다음 요소가 있어야 한다.

* 사이트 로고 또는 텍스트 로고
* 데스크톱 내비게이션
* 모바일 메뉴 버튼
* 콘텐츠 최대 너비
* 스크롤 시에도 구분 가능한 배경과 하단 경계선
* 공개 사이트 최상단의 시맨틱 `<header>`

임시 로고는 텍스트 `DotG`를 사용한다.

로고는 `/` 경로로 이동하는 Next.js `Link`여야 한다.

공개 메뉴는 `src/config/navigation.ts`의 설정값을 사용한다.

메뉴 항목은 최소한 다음 경로를 포함한다.

```text
/
 /about
/projects
/recruitment
/notices
/contact
```

메뉴 라벨은 다음과 같이 작성한다.

```text
홈
동아리 소개
프로젝트
모집 안내
공지사항
연락처
```

Header 내부에서 메뉴 배열을 다시 하드코딩하지 마라.

## 데스크톱 내비게이션

데스크톱에서는 다음 구조를 사용한다.

```html
<nav aria-label="주요 메뉴">
  <ul>
    <li>
      <a>...</a>
    </li>
  </ul>
</nav>
```

요구사항:

* 모바일 구간에서는 숨긴다.
* 충분한 클릭 영역을 제공한다.
* hover와 focus-visible 상태를 구분한다.
* 현재 경로에 해당하는 메뉴를 시각적으로 표시한다.
* 현재 메뉴 링크에는 `aria-current="page"`를 적용한다.
* 현재 경로가 `/projects/example`인 경우 `/projects` 메뉴도 활성 상태로 표시한다.
* `/notices/example`인 경우 `/notices` 메뉴도 활성 상태로 표시한다.
* 루트 `/` 메뉴는 정확히 `/`일 때만 활성화한다.

현재 경로 확인이 필요한 부분은 별도의 작은 Client Component로 분리해도 된다.

Header 전체를 불필요하게 Client Component로 만들지 마라.

# 5. 활성 메뉴 판별

현재 경로에 따른 활성 메뉴 판별 로직을 명확하게 작성한다.

권장 규칙:

```ts
function isNavigationItemActive(pathname: string, href: string): boolean {
  if (href === "/") {
    return pathname === "/";
  }

  return pathname === href || pathname.startsWith(`${href}/`);
}
```

동일한 로직이 데스크톱 메뉴와 모바일 메뉴에서 중복된다면 작은 유틸리티 함수로 분리할 수 있다.

단, 이번 작업을 위해 지나치게 많은 파일을 추가하지 마라.

가능한 위치 예시:

```text
src/components/layout/navigation-utils.ts
```

또는 `mobile-menu.tsx`와 Header에서 공통으로 사용할 수 있는 단순 함수로 구성한다.

# 6. 모바일 메뉴 요구사항

다음 파일을 구현한다.

```text
src/components/layout/mobile-menu.tsx
```

모바일 메뉴는 상호작용이 필요하므로 Client Component로 작성한다.

파일 최상단에 다음 지시어를 사용한다.

```tsx
"use client";
```

## 기본 동작

* 햄버거 버튼을 누르면 메뉴가 열린다.
* 다시 누르면 메뉴가 닫힌다.
* 메뉴 항목을 누르면 메뉴가 닫힌다.
* 현재 경로가 바뀌면 메뉴가 닫힌다.
* 데스크톱 너비에서는 모바일 메뉴가 보이지 않는다.
* 모바일 최소 너비 360px에서 가로 스크롤이 없어야 한다.

## 메뉴 버튼

버튼에는 다음 접근성 속성을 적용한다.

```tsx
aria-label="메뉴 열기"
aria-expanded={open}
aria-controls="mobile-navigation"
```

메뉴가 열렸을 때는 `aria-label`을 `"메뉴 닫기"`로 변경한다.

아이콘 패키지를 설치하지 마라.

햄버거 및 닫기 아이콘은 다음 중 하나로 구현한다.

* 간단한 inline SVG
* CSS 선 요소
* 텍스트 기반 기호

inline SVG를 사용할 경우 장식용 아이콘에는 적절한 `aria-hidden`을 적용한다.

## 모바일 내비게이션

모바일 메뉴 내부는 다음 구조를 따른다.

```html
<nav id="mobile-navigation" aria-label="모바일 주요 메뉴">
  <ul>
    <li>
      <a>...</a>
    </li>
  </ul>
</nav>
```

요구사항:

* 메뉴가 닫힌 상태에서는 화면과 접근성 트리에서 적절히 제외한다.
* 메뉴가 열렸을 때 Header 아래에 표시한다.
* 화면 전체를 가리는 복잡한 Drawer 라이브러리는 사용하지 않는다.
* 메뉴 항목의 클릭 영역을 충분히 확보한다.
* 현재 경로를 활성 상태로 표시한다.
* 활성 메뉴에는 `aria-current="page"`를 적용한다.
* 키보드 Tab으로 모든 항목에 접근할 수 있어야 한다.
* Escape 키를 누르면 메뉴가 닫히게 구현한다.
* 메뉴가 열린 상태에서 배경 스크롤 잠금은 이번 단계에서 필수가 아니다.
* 포커스 트랩은 구현하지 않아도 된다.
* 과도한 애니메이션을 사용하지 않는다.
* `prefers-reduced-motion` 사용자를 방해하지 않는다.

## 경로 변경 감지

Next.js의 현재 프로젝트 방식에 맞는 경로 훅을 사용한다.

경로가 바뀔 때 메뉴가 자동으로 닫히도록 처리한다.

# 8. 공개 사이트 레이아웃 연결

다음 파일을 수정한다.

```text
src/app/(public)/layout.tsx
```

공개 사이트의 모든 페이지에 Header와 Footer가 적용되도록 한다.

권장 구조:

```tsx
import { PublicFooter } from "@/components/layout/public-footer";
import { PublicHeader } from "@/components/layout/public-header";

export default function PublicLayout({
  children,
}: Readonly<{
  children: React.ReactNode;
}>) {
  return (
    <div className="flex min-h-screen flex-col">
      <PublicHeader />
      <main id="main-content" className="flex-1">
        {children}
      </main>
      <PublicFooter />
    </div>
  );
}
```

실제 export 방식은 기존 프로젝트의 규칙에 맞춘다.

## Skip Link

키보드 사용자를 위해 Header보다 앞에 본문 바로가기 링크를 추가한다.

예시:

```tsx
<a
  href="#main-content"
  className="..."
>
  본문 바로가기
</a>
```

요구사항:

* 평소에는 시각적으로 숨긴다.
* 키보드 focus 시 화면에 표시한다.
* `main` 요소에 `id="main-content"`를 적용한다.
* focus 표시를 제거하지 않는다.

Skip Link는 최상위 공개 레이아웃 또는 Header에 둘 수 있지만, Header보다 먼저 포커스되어야 한다.

# 9. 스타일 기준

이번 단계에서는 Header와 Footer의 완성형 브랜딩보다 사용성과 구조를 우선한다.

기본 디자인 방향:

* 게임 개발 동아리에 어울리는 어두운 계열
* 읽기 쉬운 높은 대비
* Header는 상단에 안정적으로 고정된 느낌
* 콘텐츠 최대 너비 적용
* 모바일 우선 반응형
* 단순한 경계선과 배경 구분
* 과도한 그림자 및 애니메이션 금지

가능하면 프롬프트 1에서 준비한 CSS 변수를 사용한다.

예:

```text
--background
--foreground
--surface
--border
--primary
--primary-foreground
```

색상값을 Header와 Footer 파일에 반복해서 직접 작성하지 마라.

Tailwind arbitrary value로 CSS 변수를 참조할 수 있다.

예시:

```tsx
className="bg-[var(--background)] text-[var(--foreground)]"
```

현재 프로젝트의 전역 스타일 방식이 다르다면 기존 방식을 존중한다.

# 10. 반응형 기준

최소한 다음 구간을 고려한다.

```text
모바일: 360px 이상
태블릿: Tailwind md 기준
데스크톱: Tailwind lg 기준
```

요구사항:

* 360px에서 Header 내용이 가로로 넘치지 않아야 한다.
* 데스크톱 내비게이션은 적절한 breakpoint 이상에서만 표시한다.
* 모바일 메뉴 버튼은 데스크톱 내비게이션이 표시되는 구간에서 숨긴다.
* Footer 열 구조는 모바일에서 세로, 넓은 화면에서 여러 열로 배치할 수 있다.
* 긴 메뉴 라벨이 레이아웃을 깨뜨리지 않아야 한다.
* 모바일 메뉴가 열려도 가로 스크롤이 생기지 않아야 한다.

# 11. Client Component 범위

이번 작업에서 Client Component는 최소화한다.

허용되는 Client Component:

```text
src/components/layout/mobile-menu.tsx
```

필요하다면 현재 경로 활성 표시를 위한 작은 내비게이션 컴포넌트도 Client Component로 만들 수 있다.

하지만 다음 요소는 Server Component로 유지하는 것을 우선한다.

```text
src/app/(public)/layout.tsx
src/components/layout/public-footer.tsx
Header의 정적 외곽 구조
```

Header 전체를 Client Component로 만들 경우, 그 이유를 완료 보고에 명확히 작성하라.

상태가 필요하지 않은 파일에 `"use client"`를 붙이지 마라.

# 12. import와 export 규칙

기존 코드 스타일을 먼저 확인한 후 일관되게 작성한다.

* named export와 default export를 혼용하지 마라.
* 기존 공통 컴포넌트의 export 방식을 따른다.
* `@/*` 별칭이 설정되어 있다면 상대 경로 대신 활용한다.
* 사용하지 않는 import를 남기지 않는다.
* 같은 컴포넌트를 여러 이름으로 중복 export하지 않는다.
* 불필요한 `index.ts` 배럴 파일을 만들지 않는다.

# 13. 접근성 요구사항

다음을 반드시 확인한다.

## Header

* `<header>` 사용
* 로고 링크에 의미 있는 accessible name 존재
* 데스크톱 `<nav aria-label="주요 메뉴">`
* 활성 메뉴에 `aria-current="page"`
* 모든 링크에 focus-visible 표시

## 모바일 메뉴 버튼

* 실제 `<button type="button">`
* `aria-label`
* `aria-expanded`
* `aria-controls`
* 최소한 시각적으로 충분한 클릭 영역

## 모바일 내비게이션

* `<nav aria-label="모바일 주요 메뉴">`
* 메뉴 닫힘 상태에서 불필요한 Tab 진입 방지
* Escape 키 닫기
* 메뉴 선택 후 닫기

## Footer

* `<footer>` 사용
* 빠른 링크에 적절한 `<nav aria-label="바닥글 메뉴">`

# 15. 수동 확인용 경로

구현 후 최소한 다음 경로를 확인한다.

```text
/
/about
/projects
/recruitment
/notices
/contact
/admin/login
```

확인 내용:

* 공개 경로에 Header와 Footer가 표시되는가
* `/admin/login`에 공개 Header와 Footer가 표시되지 않는가
* 로고가 `/`로 이동하는가
* 데스크톱 메뉴가 정상 노출되는가
* 모바일 메뉴가 열리고 닫히는가
* 메뉴 선택 후 모바일 메뉴가 닫히는가
* 현재 경로 메뉴가 활성화되는가
* 프로젝트 상세에서도 프로젝트 메뉴가 활성화되는가
* 공지 상세에서도 공지사항 메뉴가 활성화되는가
* 관리자 로그인 링크가 올바른 경로로 이동하는가
* 본문 바로가기 링크가 동작하는가

# 16. 검증

작업 완료 후 다음 명령을 실행한다.

```powershell
pnpm lint
pnpm build
```

오류가 발생하면 원인을 분석하고 수정한 뒤 다시 실행한다.

추가로 가능한 경우 개발 서버를 실행해 공개 경로를 확인한다.

```powershell
pnpm dev
```

다만 기존 개발 서버가 실행 중이거나 포트가 사용 중이라면 사용자 프로세스를 임의로 종료하지 마라.

그 경우 코드 검증과 실행 환경 문제를 구분해서 보고하라.

## 검증 체크리스트

* TypeScript 오류가 없는가
* ESLint 오류가 없는가
* 사용하지 않는 import가 없는가
* Header와 Footer가 공개 Route Group에만 적용되는가
* 관리자 경로에는 공개 레이아웃이 적용되지 않는가
* Client Component 범위가 최소화되어 있는가
* 현재 경로 활성 표시가 정확한가
* 루트 메뉴가 다른 모든 경로에서 활성화되지 않는가
* 모바일 메뉴의 Escape 닫기가 동작하는가
* `aria-expanded` 값이 상태와 일치하는가
* 360px 화면에서 가로 스크롤이 없는가
* 환경 변수가 없어도 빌드되는가
