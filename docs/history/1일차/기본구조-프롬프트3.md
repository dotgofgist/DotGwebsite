현재 작업 중인 저장소는 게임창작부 동아리 웹사이트 프로젝트다.

이번 작업은 7단계 중 **프롬프트 3: 메인 페이지, 동아리 소개, 연락처 및 SNS 배너 구현**에 해당한다.

이전 단계에서 다음 작업이 완료되었다고 가정한다.

* Next.js App Router 기반 공개 및 관리자 라우팅 골격
* `src/app/(public)` 공개 Route Group
* 공개 사이트 Header
* 공개 사이트 Footer
* 데스크톱 내비게이션
* 모바일 햄버거 메뉴
* 공통 UI 컴포넌트
* 사이트 설정 파일
* 내비게이션 설정 파일
* 전역 스타일
* 임시 공개 페이지

기존 구현을 먼저 확인하고 실제 파일 상태에 맞춰 필요한 부분만 수정하라.

프로젝트 전체를 재생성하거나 기존 공통 레이아웃을 임의로 교체하지 마라.

# 6. SNS 설정

다음 파일을 생성한다.

```text
src/config/social.ts
```

다음 타입을 정의한다.

```ts
export type SocialLink = {
  name: string;
  label: string;
  href: string;
  description?: string;
};
```

임시 SNS 항목은 다음 네 개를 포함한다.

```text
GitHub
Instagram
YouTube
Discord
```

실제 URL이 제공되지 않았으므로 유효한 실제 계정 주소를 추측하지 마라.

임시 URL은 다음처럼 명확한 placeholder 형식으로 작성한다.

```ts
export const socialLinks: SocialLink[] = [
  {
    name: "GitHub",
    label: "GitHub",
    href: "#",
    description: "프로젝트 저장소와 개발 기록",
  },
];
```

단, `href="#"` 링크는 실제로 클릭 시 페이지 상단으로 이동해 사용성을 해칠 수 있으므로 다음 중 하나를 선택하라.

* 비활성 상태로 렌더링
* 버튼 형태가 아닌 텍스트 카드로 렌더링
* `aria-disabled="true"` 적용
* 클릭 이벤트 없이 미정 상태를 표시

실제 URL이 없는 항목을 작동하는 외부 링크처럼 보이게 만들지 마라.

향후 실제 URL만 교체하면 되도록 설정 구조를 유지하라.

아이콘 패키지는 설치하지 마라.

SNS 표시는 다음 중 하나로 구현한다.

* 텍스트 로고
* 간단한 inline SVG
* 원형 이니셜
* 서비스 이름

# 7. 연락처 설정

다음 파일을 생성한다.

```text
src/config/contact.ts
```

권장 타입:

```ts
export type ContactItem = {
  label: string;
  value: string;
  href?: string;
  description?: string;
};
```

확정된 이메일 주소, 전화번호, 오픈채팅 링크 등이 없으므로 임의의 실제 값을 생성하지 마라.

다음과 같은 구조만 준비한다.

```ts
export const contactItems: ContactItem[] = [
  {
    label: "일반 문의",
    value: "공식 연락처 준비 중",
    description: "문의 채널이 확정되면 이곳에 안내됩니다.",
  },
];
```

사용자에게 노출되는 placeholder 문구는 최소화한다.

가능하면 연락처 페이지에서 다음 메시지를 자연스럽게 제공한다.

```text
현재 공식 연락 채널을 정리 중입니다.
지원 관련 안내는 모집 페이지에서 확인해 주세요.
```

`mailto:` 또는 전화번호 링크는 실제 값이 있을 때만 작성하라.

예시 문구:

```text
게임을 만들고,

```

설명 예시:

```text
DotG는 기획, 프로그래밍, 아트, 사운드 등 다양한 분야의 구성원이 함께 게임을 만드는 창작 동아리입니다.
```

요구사항:

* 모바일에서 텍스트와 버튼이 세로로 배치된다.
* 넓은 화면에서는 텍스트와 시각 요소를 2열로 배치할 수 있다.
* 버튼은 키보드 접근이 가능해야 한다.
* 장식 요소에는 불필요한 접근성 정보가 노출되지 않아야 한다.
* 배경 영상이나 자동 재생 애니메이션은 사용하지 않는다.
* 외부 이미지 다운로드는 하지 않는다.
* 임시 그래픽은 CSS와 HTML만으로 구현한다.

# 27. Server Component 원칙

이번 단계의 컴포넌트는 기본적으로 모두 Server Component로 작성한다.

새로운 Client Component를 만들지 마라.

다음 기능은 필요하지 않다.

* 상태 관리
* 브라우저 이벤트
* `useEffect`
* `useState`
* `usePathname`
* 사용자 입력 폼
* 동적 토글

기존 Header의 모바일 메뉴 Client Component는 수정하지 않는 것을 원칙으로 한다.

정말 수정이 필요한 경우 기존 동작을 유지하고 범위를 최소화하라.

# 28. 접근성 요구사항

다음을 반드시 준수한다.

## 문서 구조

* 각 페이지에 하나의 `<h1>`
* 섹션 제목은 논리적인 heading 순서 사용
* 주요 콘텐츠는 `<section>` 사용 가능
* 단순 배치용 요소에 불필요한 landmark 역할을 부여하지 않는다

## 링크

* “자세히 보기”만 반복하지 말고 목적이 드러나는 링크 이름 사용
* 외부 링크는 새 탭 열림 여부가 이해 가능해야 한다
* 실제 URL이 없는 항목을 가짜 링크로 만들지 않는다
* 모든 링크에 focus-visible 표시

## 장식 요소

* 장식용 SVG에는 `aria-hidden="true"`
* 의미 없는 아이콘에 alt 텍스트를 넣지 않는다
* CSS 장식 요소는 접근성 트리에 노출하지 않는다

## 색상

* 색상만으로 상태를 구분하지 않는다
* 배지에는 텍스트 상태를 함께 표시한다
* 텍스트 대비를 충분히 확보한다
