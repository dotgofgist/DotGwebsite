# 8. 환경 변수 접근 계층

다음 파일을 구현한다.

```text
src/lib/supabase/env.ts
```

목표는 Supabase 환경 변수 확인 로직을 한곳에 모으는 것이다.

권장 타입:

```ts
export type SupabasePublicEnv = {
  url: string;
  publishableKey: string;
};
```

최소한 다음 함수를 제공한다.

```ts
export function getSupabasePublicEnv(): SupabasePublicEnv | null;

export function requireSupabasePublicEnv(): SupabasePublicEnv;

export function isSupabaseConfigured(): boolean;
```

## `getSupabasePublicEnv()`

다음 환경 변수를 읽는다.

```text
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
```

둘 중 하나라도 없거나 빈 문자열이면 `null`을 반환한다.

모듈 import 시점에 throw하지 않는다.

## `requireSupabasePublicEnv()`

환경 변수가 있으면 반환한다.

없으면 개발자가 원인을 이해할 수 있는 오류를 throw한다.

오류 메시지 예시:

```text
Supabase 환경 변수가 설정되지 않았습니다.
.env.example을 참고하여 .env.local을 구성하세요.
```

Key 값이나 URL 전체를 오류 메시지에 출력하지 마라.

## `isSupabaseConfigured()`

두 환경 변수가 모두 존재할 때만 `true`를 반환한다.

## URL 검사

필요하다면 `new URL()`을 사용해 URL 형식을 확인할 수 있다.

유효하지 않은 URL은 설정되지 않은 것으로 처리하거나 명확한 오류를 반환한다.

복잡한 환경 변수 검증 라이브러리를 설치하지 마라.

Zod를 설치하지 마라.

# 9. 브라우저용 Supabase 클라이언트

다음 파일을 구현한다.

```text
src/lib/supabase/client.ts
```

`@supabase/ssr`의 브라우저 클라이언트를 사용한다.

목표 API:

```ts
export function createClient() {
  // 브라우저용 Supabase client 반환
}
```

또는 프로젝트의 naming convention이 명확하다면 다음 이름을 사용할 수 있다.

```ts

```

## 요구사항

* `createBrowserClient`를 사용한다.
* `Database` 타입을 generic으로 적용한다.
* 환경 변수는 `requireSupabasePublicEnv()`를 통해 읽는다.
* 실제 함수가 호출되기 전에는 throw하지 않는다.
* 모듈 최상위에서 client instance를 생성하지 않는다.
* Key를 코드에 하드코딩하지 않는다.
* Key를 console에 출력하지 않는다.
* Secret Key를 사용하지 않는다.
* 현재 단계에서는 어느 페이지에서도 이 클라이언트를 호출하지 않는다.
* 불필요하게 Client Component를 추가하지 않는다.

설치된 `@supabase/ssr` 버전의 실제 API와 타입을 확인해 작성한다.

과거 버전의 API를 추측하지 마라.

# 10. 서버용 Supabase 클라이언트

다음 파일을 구현한다.

```text
src/lib/supabase/server.ts
```

Next.js Server Component, Server Action, Route Handler에서 향후 사용할 서버 클라이언트 생성 함수를 준비한다.

목표 API:

```ts
export async function createClient() {
  // 서버용 Supabase client 반환
}
```

또는 이름 충돌 방지를 위해 다음 이름을 사용할 수 있다.

```ts
export async function createServerSupabaseClient() {
  // ...
}
```

## 요구사항

* `createServerClient`를 사용한다.
* Next.js의 `cookies()` API를 사용한다.
* 현재 설치된 Next.js 버전의 비동기 API 규칙을 따른다.
* `Database` 타입을 generic으로 적용한다.
* 환경 변수는 `requireSupabasePublicEnv()`에서 가져온다.
* cookie의 `getAll`과 `setAll` 처리를 설치된 패키지 타입에 맞춘다.
* Server Component에서 쿠키 쓰기가 허용되지 않는 상황을 안전하게 처리한다.
* 인증 쿠키 갱신은 Proxy가 담당한다는 주석을 남길 수 있다.
* 실제 DB query는 작성하지 않는다.
* 서버 모듈에 `"use client"`를 추가하지 않는다.
* 모듈 최상위에서 client를 생성하지 않는다.
* 환경 변수가 없으면 함수가 호출될 때만 오류를 발생시킨다.

`cookies()`의 실제 반환 타입과 `@supabase/ssr`의 cookie option 타입을 확인하여 TypeScript 오류가 없게 작성한다.

`any`로 타입 오류를 우회하지 마라.

# 11. Supabase Proxy helper

다음 파일을 구현한다.

```text
src/lib/supabase/proxy.ts
```

목표는 향후 Supabase Auth 세션 쿠키를 갱신할 수 있는 함수를 준비하는 것이다.

권장 함수 이름:

```ts
export async function updateSession(request: NextRequest): Promise<NextResponse>;
```

## 요구사항

* `NextRequest`와 `NextResponse`를 사용한다.
* 환경 변수가 없으면 오류를 발생시키지 않고 `NextResponse.next()`를 반환한다.
* 환경 변수가 있으면 서버 클라이언트를 생성하고 인증 세션 확인을 수행할 수 있다.
* 응답 쿠키가 원본 response에 반영되도록 작성한다.
* 설치된 `@supabase/ssr`의 현재 cookie API에 맞춘다.
* 환경 변수나 토큰을 로그로 출력하지 않는다.
* 현재 단계에서는 로그인 여부에 따른 redirect를 구현하지 않는다.
* `/admin` 보호를 구현하지 않는다.
* 권한 검사를 구현하지 않는다.
* 역할 검사를 구현하지 않는다.
* 로그인 페이지 redirect loop를 만들지 않는다.

세션 갱신을 위해 Supabase 사용자 확인 메서드를 호출할 경우, 설치된 SDK의 권장 인증 API를 사용한다.

오래된 세션 API를 추측해서 사용하지 마라.

# 12. Next.js 루트 Proxy

다음 파일을 생성하거나 수정한다.

```text
src/proxy.ts
```

현재 설치된 Next.js 버전이 `proxy.ts` convention을 사용하는지 확인한다.

기존 프로젝트에 `middleware.ts` 또는 다른 Proxy 구현이 있다면 충돌하지 않도록 처리한다.

중복해서 두 파일이 같은 역할을 수행하게 만들지 마라.

권장 역할:

```ts
import type { NextRequest } from "next/server";

import { updateSession } from "@/lib/supabase/proxy";

export async function proxy(request: NextRequest) {
  return updateSession(request);
}
```

실제 export 이름은 설치된 Next.js 버전의 file convention에 맞춘다.

## Matcher

정적 자산과 이미지 요청은 불필요한 Proxy 실행에서 제외한다.

예시로 다음 항목을 고려한다.

```text
_next/static
_next/image
favicon.ico
일반 이미지 확장자
```

matcher는 지나치게 복잡하게 만들지 않는다.

다음 경로는 Proxy 적용 대상에 포함될 수 있다.

```text
/
/about
/projects
/notices
/recruitment
/contact
/admin
```

하지만 현재는 어떤 경로도 인증 때문에 redirect하지 않는다.

## 환경 변수 미설정

Supabase 환경 변수가 없는 상태에서도 모든 페이지가 정상적으로 동작해야 한다.

Proxy가 환경 변수 누락 때문에 요청을 실패시키면 안 된다.

현재 실제 Supabase 스키마가 없으므로 가짜 테이블 타입을 작성하지 마라.

```ts
export type Json =
  | string
  | number
  | boolean
  | null

};
```
