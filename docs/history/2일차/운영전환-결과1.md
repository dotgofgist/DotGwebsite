완료했습니다. 핵심은 `dotg-web` 기준으로 Supabase 환경 판별을 공통화하고, local/Preview/Production의 fallback 정책을 코드와 문서, 테스트에 같이 박아 넣은 작업입니다.

**1. 기존 구조 분석**
- 실제 Next 앱 루트는 `dotg-web`.
- Next.js `16.2.11`, App Router 사용.
- 기존 Supabase env는 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 보고 있었고, 요청 기준인 `NEXT_PUBLIC_SUPABASE_ANON_KEY`와 불일치했습니다.
- 공개 query fallback은 기능별로 흩어져 있었고, public notices는 Supabase 조회가 실제로 연결되지 않은 상태였습니다.
- 설정 누락 상태에서 운영 build가 mock/config fallback으로 조용히 넘어갈 위험이 있었습니다.
