# DotG 출시단계 진입 전 현황 점검 결과

## 1. 요약

현재 `dotg-web`는 Next.js App Router 기반 공개 사이트, 관리자 사이트, Supabase DB/Auth/Storage, CI/CD, E2E, release gate까지 대부분 구현되어 있습니다.  
로컬 검증 기준으로 TypeScript, lint, build, DB SQL tests, RLS/storage checks, Playwright E2E, SEO/a11y smoke, `release:check`가 모두 통과했습니다.  
공개 데이터는 Supabase query를 우선 사용하고, local에서 Supabase 미설정일 때만 mock/config fallback을 허용합니다. preview/production fallback 차단 테스트도 있습니다.  
관리자 페이지는 `editor/admin`만 접근 가능하고, `member`는 E2E에서 차단 검증됩니다.  
출시단계 진입을 막는 build/RLS/Auth/secret 노출 문제는 발견하지 못했습니다.  
다만 일부 사용자 노출 한국어 문자열이 mojibake로 깨져 저장되어 있어, 실제 공개 전 문구 복구 검수가 필요합니다.  
Supabase/GitHub/Vercel/도메인 Dashboard의 실제 설정 상태는 저장소만으로 확인 불가입니다.

## 5. Supabase 현황

* schema: `profiles`, `projects`, `project_members`, `project_links`, `notices`, `recruitments`, `recruitment_steps`, `site_settings`, `contact_items`, `social_links` 존재.
* migration: 6개 migration 순서 검증 통과. destructive drop/truncate 없음.
* enum/type: `content_status`, `project_status`, `project_link_type`, `recruitment_status`, `user_role`.
* seed: `supabase/seed.sql`은 개발 mock data 포함. `supabase/seeds/production.sql`은 `site_settings` 최소 baseline만 `on conflict do nothing`으로 생성.
* RLS: anon은 published/active 공개 조회만 가능. authenticated member는 관리자 write 불가. editor/admin은 content manage 가능. admin은 profile role update 가능.
* Auth: `handle_new_user`로 profile 자동 생성. `can_manage_content`, `is_admin` security definer helper는 `search_path` 고정.
* Storage: `project-images`, `site-assets` bucket 생성, public read, content manager upload/update/delete policy. DB에는 public URL이 아니라 object path 저장.
* remote deployment tooling: preflight, migration list, db push, production seed, remote smoke, remote RLS check, remote type generation, bootstrap/admin status snippets 존재. 실제 remote 실행은 외부 설정 필요.

## 8. SEO / 접근성 / 운영 품질

SEO는 `metadataBase`, canonical, Open Graph, Twitter, favicon, manifest, robots, sitemap, project/notice detail metadata가 구현되어 있고 E2E smoke를 통과했습니다. 실제 production canonical/domain은 `NEXT_PUBLIC_SITE_URL` 또는 Vercel production URL 설정이 필요합니다.

접근성은 skip link, heading/form label, `aria-current`, mobile nav ARIA, error `role=alert`/`aria-live`, external link `rel` 처리가 보입니다. axe 자동 검증은 통과했지만 실제 screen reader 수동 QA와 Lighthouse 실환경 점검은 저장소만으로 확인 불가입니다.

운영 품질에서 가장 눈에 띄는 문제는 일부 한국어 UI/에러/SQL seed 문자열이 깨진 상태로 저장되어 있다는 점입니다. 기능 테스트는 통과하지만 실제 사용자 화면 품질 검수 대상입니다.

## 11. 출시단계에서 실제로 해야 할 작업

1. 현재 Git 문서 변경사항 정리: rename 의도 확인 후 commit 대상/제외 대상 결정.
2. 깨진 한국어 사용자 노출 문자열 전수 복구 및 UI 문구 QA.
3. Supabase production project 생성/연결, migrations preflight, production seed 적용, admin bootstrap.
4. Vercel project 연결 및 Preview/Production env 설정.
5. GitHub `preview`/`production` Environment, secrets, required reviewer, branch protection 설정 확인.
6. production URL/domain/DNS 확정 후 `NEXT_PUBLIC_SITE_URL` 설정.
7. Preview deployment smoke, remote Supabase RLS/read-only smoke, production dry-run 절차 확인.
8. 실제 production 배포 후 smoke, Lighthouse, 수동 브라우저 QA, screen reader QA 수행.
