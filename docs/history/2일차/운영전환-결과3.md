**1. 기존 인증·권한 구조 분석**
- 로그인은 `/admin/login` Server Action에서 Supabase Auth `signInWithPassword()` 후 `profiles.role`을 확인합니다.
- proxy는 세션 cookie 갱신과 비로그인 `/admin` 접근 redirect를 담당합니다.
- 관리자 layout은 `requireContentManager()`로 `editor/admin`만 통과시킵니다.
- 대부분의 관리자 Server Action은 `requireContentManager()`를 사용했지만, 일부는 입력 검증 후 권한 확인을 했습니다.
- admin 전용 공통 helper가 없었고, `next` redirect 방어가 double-encoding/backslash/control character까지는 명시적으로 막지 않았습니다.

**8. 수동 검증**
실제 브라우저 계정별 검증은 수행하지 않았습니다. 원격/실계정 member/editor/admin credentials가 제공되지 않았기 때문에 문서 체크리스트로 남겼습니다.
